# 画面仕様：ピクルス詳細（S6）

`docs/spec.md` の S6「ステッカー詳細」と、機能 6 の完了条件を画面に落としたもの。画面に出す呼び方は「ピクルス」にする。コード、URL、Lexicon の呼び方（`sticker`）は変えない。

- URL：`/sticker/:did/:rkey`（今のまま）
- 実装：`frontend/src/pages/StickerDetail.tsx`
- 開くところ：タイムライン、ビン（シール帳）、ビンの手持ち一覧、共同フィールド、交換成立の表示

## 1. レイアウト

上から下へこの順に並べる。縦にスクロールする1カラム。見た目は Figma の「ピクルス」（node `29:357`）に合わせる。背景はアプリ共通の `--color-bg`。

## 2. 各部の中身

### ① ピクルス

| 項目 | 元のデータ | 表示 |
| --- | --- | --- |
| 画像 | `sticker.image` | 今の `StickerImage` を使う。中央揃えで、高さの上限は 220px |

### ② 種類・日時とピクルス名

| 項目 | 元のデータ | 表示 |
| --- | --- | --- |
| 種類 | `sticker.source` | タグ（`.tag`）。`photo` →「写真」、`illustration` →「イラスト」 |
| 日時 | `sticker.createdAt` | `2026/10/25 14:30につくった`（撮った日時。イラストは保存した日時）。灰色の小さい文字 |
| ピクルス名 | `sticker.caption` | 24px で左揃え。空なら行ごと出さない（6章のとおり、`caption` は「一言」からピクルス名に役目を変える） |

種類と日時はタグを先にして1行に並べ、その下にピクルス名を置く（spec 3章 機能 6 の完了条件にあるので残す）。

### ③ プロフィールカード（作った人）

作った人（URL の `did`）の Bluesky のプロフィールを `app.bsky.actor.getProfile` で読んで表示する。Pikkles で新しくデータを持つことはしない。

| 項目 | 元のデータ | 表示 | 無いとき |
| --- | --- | --- | --- |
| アイコン | `avatar` | 丸く切り抜く。38px | 今の `Avatar` と同じ、色の付いた丸にハンドルの頭の1文字 |
| ペンネーム | `displayName` | 太字 | ハンドルを代わりに出す |
| Bluesky の ID | `handle` | `@handle`、薄い灰色 | DID を出す |
| 自己紹介 | `description`（Bluesky の自己紹介文） | 薄い背景の箱に入れる。改行はそのまま出し、2行を超えたら「…」で切る | 箱ごと出さない |

- カードは白い背景に細い枠。左上に「作成者」の小さいラベルを置く
- プロフィールが読めないとき（通信の失敗など）：今の `Handle` と同じく、ハンドルか DID だけを出す
- カードを押すと、作った人の Bluesky のプロフィール（`https://bsky.app/profile/{did}`）を新しいタブで開く（2026-10-25変更）

### ④ 交換の記録カード

**出す条件**：自分の PDS にある `exchange` のうち、`received.uri` がこのピクルスの URI と一致するものがあるとき。無ければカードを出さない（自分のピクルス、交換していない他人のピクルス）。

| 項目 | 元のデータ | 表示 | 無いとき |
| --- | --- | --- | --- |
| 日時 | `exchange.createdAt` | `2026/10/25 14:30` | ―（必ずある） |
| 場所 | `exchange.occasion` | 交換を始めた人が手で入れた場面 | 行ごと出さない |
| コメント | 相手の PDS の `exchange.message`（6章） | 交換のときに相手が添えた一言。ラベルの下に本文を出す | 行ごと出さない |

- カードは薄い緑の背景（`--color-exchange-bg`）に細い枠。見出し「交換の記録」は緑の太字。行どうしは線で区切る
- 交換相手は書かない。もらったピクルスの作った人＝交換相手なので、③のカードがその人になる
- 同じピクルスを2回以上もらった記録があるときは、新しい順にカードを並べる
- 「受け取った／渡した」は書かない
- 場所は spec 2章のルールのとおり手入力の値。GPS などの位置情報は使わない

### ⑤ 削除

自分のピクルス（URL の `did` が自分）のときだけ、カードの下に横幅いっぱいのボタン（`.btn .btn-block`）で出す。Figma にはまだ無い。確認の文言は「このピクルスを削除しますか？」にする。

## 6. 一言を「交換のときに相手へ渡すもの」に変える（2026-10-25 許可を得て入れた）

今の一言（`sticker.caption`）は、ピクルスを作るときに付けて、誰が見ても同じものが出る。これを、交換のときに相手1人へ渡すものに変える。

10-25 01:20 以降は新しい機能を足さない決まりだが、Lexicon の変更も含めて許可を得て入れた。

### 6.1 データ

`exchange` に任意の項目を1つ足す。PDS には自分しか書けないので、渡す側が自分の `exchange` に書く。

```text
app.<ns>.exchange
  message    string    任意、最大100文字。この交換で相手に渡す一言（追加）
```

- Lexicon：`maxGraphemes: 100`、`maxLength: 1000`（spec 5章の決まりのとおり）
- 任意の項目を足すだけなので、今までの `exchange` のレコードはそのまま有効
- 成立の条件（spec 6章）には入れない。2人の `message` は別々の値でよく、サーバーは照合しない

`sticker.caption` は消さずに、役目を「ピクルス名」に変える。

- 項目の名前（`caption`）は変えない。PDS に書き始めたあとなので、名前を変えると今までのデータが読めなくなる
- Lexicon の `description` を「ピクルス名（任意）」に書き換える
- 今までに入っている一言は、そのままピクルス名として出る

### 6.2 画面

| 画面 | 変えること |
| --- | --- |
| S3 撮影・ステッカー化 | 入力欄の名前は「どんな味？」のまま。入れたものをピクルス名として出す |
| S5 対面交換 | 渡すピクルスを選んだあと、確定の前に「相手にひとこと（任意・100文字まで）」の入力欄を出す。確定したあとは変えられない |
| S5 成立表示 | 相手からの一言があれば、もらったピクルスの下に出す |
| S6 ピクルス詳細 | ④に相手からの一言を「コメント」の行として出す（6.3） |

### 6.3 ピクルス詳細での読み方

相手が書いた一言は相手の PDS にあるので、次の順に読む。

1. 自分の PDS の `exchange` から、`received.uri` がこのピクルスのものを探す（今と同じ）
2. 見つかった記録の `partner` の PDS で `exchange` を `listRecords` し、`sessionId` が同じものを探す
3. その `message` を「コメント」の行に出す。見つからない、読めない、空のときは行ごと出さない

相手の PDS を読むのは、日時と場所を出したあとでよい（その間は行を出さない）。

### 6.4 `docs/spec.md` で直したところ

- 3章の「作らない」から「交換時に相手のステッカーへ手書きの一言を添える」を外す（入力するのは手書きではなく文字）
- 3章 機能 6 の完了条件の「一言」を「ピクルス名、相手からの一言」にする
- 4章の S3 の「一言」を「ピクルス名」に、S5 に「相手への一言」を足す
- 5章の `sticker.caption` の説明を変え、`exchange.message` を足す
